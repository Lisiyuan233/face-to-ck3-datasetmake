# CK3 训练对比报告：本次 105865 数据集 vs 上月 34780 数据集

报告时间：2026-09-01（初版 01:12 UTC，终版更新 05:40 UTC）| 数据：105865_v2 30/30 epoch 已完成

## 一、对比对象

| | 上月（2026-08-20，WSL 工作站） | 本次（2026-08-31 起，256ram） |
|---|---|---|
| 数据集 | `face_to_ck3_dataset_male_small`（34,780 样本） | 同名目录扩充后（105,865 样本，×3.05） |
| 训练结构 | v1 全新 30 ep + v2 热启动 20 ep（共 50 ep） | v1 全新 30 ep（已完成）+ v2 热启动 30 ep（进行中，ep5） |
| 热启动方式 | v1 best.pt EMA，调度从头 | v1 last.pt EMA，调度从头（同上月做法） |
| 模型/超参 | ConvNeXt-Tiny multiview，bs16×2，lr 1e-4/3e-4，30ep | 完全相同（仅 amp 由 bf16 配置钉死为 fp16，实际运行精度不变） |
| 硬件 | **单卡 4060 Ti 16G**（WSL /mnt/d），60.3 samples/s，实际精度 **bf16**（Ada 原生支持） | **3 卡 2080 Ti 22G** DDP（256ram），51.4 samples/s/卡，实际精度 **fp16** |
| 每 epoch（含验证） | ~9.0 分钟（31,456 样本） | ~11.0 分钟（95,281 样本） |

精度说明：上月 4060 Ti 原生支持 bf16，配置 bf16 直接生效、无任何问题；本月 2080Ti 无 bf16
cuDNN 引擎，105865_v1 启动时已改用 fp16（resolved config 可证，磁盘配置文件仍写 bf16），
本轮 v2 显式钉死 fp16。详见 `CK3_105865_ROUND2_WARMSTART_TRAINING.md` 第三节。

## 二、可比性声明（先读）

1. **验证集不同**：上月 val=1,688 样本（34,780 数据集切分），本次 val=5,293 样本
   （105,865 数据集切分）。两次绝对数值**不是同一口径**，跨月对比只能作方向性判断。
2. **schema 有差异**：核心任务字段完全一致（67 signed + 16 categorical，逐字段同名），
   新增 3 个 color 字段（eye/hair/skin_color）。逐字段对比建立在 67 个共同字段上，有效。
3. **数据扩充性质**：按扩充方案（`CK3_SYNTHETIC_DATASET_EXPANSION_PLAN.md`），
   新增主要是合成随机样本与弱字段干预样本，分布与原 34,780 不完全相同。
4. 【终版】v2 已跑完 30/30 epoch，终值全面反超上月：总分 -32%、signed -31%、strength -20%；逐字段 65/67 反超（详见字段对比文档）。

**读法**：

- **val_score 总分**：本次热启动第 5 个 epoch（0.07471）已越过上月 50 epoch 的最终值
  （0.07597）。同样越过 v1→v1 的对比：本次仅 30 epoch 就到 0.07822，上月 30 epoch 为 0.09252。
- **分项拆解**（score = 0.4×signed + 0.25×strength + 0.35×categorical 误差加权）：
  本次的优势全部来自**分类侧**（cat_acc +1.5pp、observable_macro_f1 +0.9pp）；
  **连续侧（signed/strength）上月最终值仍分别领先约 2.8% / 3.2%**，本轮正在追赶
  （5 个 epoch 收敛 0.0782→0.0747，斜率未衰竭，尚有 25 个 epoch 余量）。

## 六、收敛与算力效率

| | 上月 | 本次 |
|---|---|---|
| v1 达到自身 v2 起点的耗时 | —（50 ep 累计 7.1h 到 0.0760） | v1 30ep 5.5h 到 0.0782 |
| 热启动每 epoch 平均收益 | 0.0925→0.0760，-0.00083/ep | 0.0782→0.0747，**-0.00070/ep**（前 5 ep） |
| 总样本通过量 | 50 ep × 31.5k ≈ 157 万 | v1 已 286 万；v2 全程后合计 ≈ 572 万 |
| 每 epoch 墙钟 | 8.5~8.6 min | ~11 min（数据 ×3，3 卡聚合吞吐 ~162/s 对上月单卡 60.9/s） |

吞吐为跨卡型对比：4060 Ti 16G 单卡 60.3 vs 2080 Ti 22G 单卡当量 51.4（约 -15%，Ada 架构与
新版 tensor core 优势，2080Ti 虽显存带宽翻倍但此负载下不占优；另有 DDP 通信与精度差异）。
3 卡 2080Ti 聚合 ≈154 samples/s，为 4060 Ti 单卡的 2.56 倍。

## 七、结论与建议

1. **数据 ×3 是正收益**：同阶段（v1 30ep）val_score 0.0925 → 0.0782（-15.5%），分类侧提升显著。
2. **连续侧尚未收复**：signed/strength 仍差上月最终值 3% 左右，但本轮尚余 25 个 epoch、
   改善斜率未衰竭，按当前斜率外推**有望在跑完时全面反超**（ep5 已越过的总分即证明组合收益为正）。
3. **逐字段有明确损益清单**：颈部/头顶/前突与部分眼部字段退步，若跑完仍未收复，
   建议按扩充方案第二条线补"弱字段单变量干预样本"定向补强，而不是继续随机扩容。
4. **工程教训沉淀**：bf16→fp16 的坑两月都遇到（上月侥幸回退、本月显式钉死），
   建议落实 `engine.py` 的 `is_bf16_supported(including_emulation=False)` 修复。
