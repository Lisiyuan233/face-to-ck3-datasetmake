# Face to CK3 DNA 完整训练方案

> 基于当前仓库中 510,000 组 CK3 男性合成肖像与 DNA 标签制定。版本 v1.0，日期 2026-07-21。

## 执行摘要

本项目的目标不是“识别人脸身份”，而是把一张经过对齐的正脸图像映射为可写回 CK3 男性 DNA 模板的脸部参数。当前数据基础已经完成：510,000 张图像全部预处理成功，标签全部匹配，官方划分为 459,000/25,500/25,500，覆盖 17 个等量数据块。仓库目前具备采集、标签归一化、反归一化和 WebDataset 预处理能力，但尚无模型、训练器、评估器和推理服务代码，因此训练部分应按“从可验证基线到真实照片域适配”的绿地项目实施。

推荐主线是：先训练可解释的多任务基线，再升级为几何/颜色双视图模型，最后加入“预测 DNA 回到 CK3 后是否像”的渲染闭环。`race_group` 仅用于分层抽样和分组评估，绝不能作为模型输入。第一版产品范围明确限制为男性；真人照片泛化必须单独验收，不能用合成测试集成绩替代。

**建议决策：** 以 ImageNet 预训练的 ConvNeXt-Tiny 为生产候选骨干；用 67 个有符号回归目标、16 个强度目标、10 个有效多类别头和 6 个颜色坐标构成多任务输出。6 个只有单一类别的字段不训练分类头，只预测其强度并在导出时写回固定 allele。完整训练预留约 48 GPU 小时作为单卡现代 24 GB GPU 的规划预算，实际预算以 2,000 step 吞吐基准为准。

## 当前资产与事实基线

### 已确认的数据资产

| 项目 | 已确认状态 | 训练含义 |
|---|---:|---|
| 原始/处理后样本 | 510,000 / 510,000 | 无跳过、无缺失标签，可直接进入训练准备门禁 |
| 官方划分 | 459,000 / 25,500 / 25,500 | 固定 seed `20260718`，不得在实验间改变 |
| 数据块 | 17 × 30,000 | 每块精确为 27,000/1,500/1,500 |
| 图像输入 | 256 × 384 RGB JPEG | 固定正脸裁剪 `(150,20,690,830)`，tar 不压缩 |
| WebDataset 分片 | 230 / 13 / 13 | 每片最多 2,000 样本，适合顺序 I/O |
| 标签 | 67 signed、16 categorical+strength、3 组颜色 | 颜色为 CK3 二维调色板坐标，不是 RGB |
| 预处理结果 | 0 skipped、0 unmatched | 正式训练不得开启 `--skip-invalid` |

当前 `dna_schema.json` 显示 16 个 categorical 字段中有 6 个字段在 51 万样本里只有一个类别。这些类别没有学习价值，保留强度回归即可。主要类别不平衡集中在 `gene_bs_nose_profile`（最大/最小约 21.5 倍）和 `face_detail_nasolabial`（约 13.6 倍），应在损失层处理，不建议按单个字段过采样，因为一个样本同时服务多个任务。

### 必须先解决的数据口径问题

仓库中的 `制作记录.txt` 仍记录“每 20,000 张一个族群”的早期片段，而且最后一个区间存在明显笔误；正式 `manifest.json` 和当前预处理代码使用的是每组 30,000、共 17 组。训练与评估一律以 manifest 为事实源。在为组号补充真实族群名称前，必须重新核对采集日志；没有可靠映射时只保留 `race_group=0..16`，不要猜测名称。

### 问题定义

输入是经人脸检测与相似变换对齐后的 `256×384` RGB 正脸。输出与现有 JSONL 标签完全一致：

- `signed[67]`：范围 `[-1,1]`，推理端用符号选择正/负 allele，用绝对值恢复强度。
- `categorical_class[16]`：每个字段独立词表；仅对 10 个多类别字段学习 logits。
- `categorical_strength[16]`：范围 `[0,1]`，包括 6 个固定类别字段。
- `colors[6]`：发色、肤色、眼色各两个 CK3 调色板坐标，范围 `[0,1]`。

逆映射本身可能多解：不同 DNA 组合可能得到相近肖像，而低强度 allele 几乎不可见。因此最终质量判断必须同时包含标签误差、分组稳健性和 CK3 回渲染相似度，不能只看某个平均 MAE。

## 数据准备与质量门禁

### 数据版本冻结

每次正式训练前生成并保存以下版本信息：Git commit、`manifest.json` SHA-256、`dna_schema.json` SHA-256、训练配置、容器/环境锁文件、预训练权重标识和随机种子。模型包必须与 schema 绑定；schema 校验和不一致时，推理程序应拒绝加载。

### 必做检查

1. 核对 manifest：`processed=510000`、`skipped=0`、`matched_labels=510000`、`unmatched_labels=0`，图像尺寸只有 `1326×891`。
2. 每个 `race_group` 随机抽查至少 100 张裁剪图，检查头顶、耳朵、下巴是否完整，正侧脸边界是否侵入。
3. 使用感知哈希检测跨 train/val/test 的近重复图像；若有重复，按重复簇整体重新分配，避免泄漏。
4. 统计每个字段的零强度比例、分位数、类别频数及字段相关性；保存为版本化报告。
5. 额外建立“时间漂移压力集”：每个连续采集块保留一小段时间连续样本，只用于诊断采集漂移，不替代官方验证集。
6. 验证 WebDataset 中 `.jpg` 与 `.json` basename 一致，随机读取 10 个分片并完成解码、标签长度和数值范围检查。

### 数据加载策略

训练集使用 shard shuffle（建议缓冲区不少于 50 个分片）加样本 shuffle（建议不少于 10,000）。验证和测试禁止随机增强、禁止重采样，样本顺序固定。每个 epoch 的训练随机种子由“全局 seed + epoch + rank”推导，确保 DDP 下可复现且各 rank 不重复。

17 个组本身等量，不需要按组过采样；只需监控每个 batch 的组分布和每组指标。categorical 类别不平衡通过字段内损失权重解决。

## 模型方案

### 基线 B0：链路正确性模型

使用 ResNet-18、输入 `128×192`，训练 5 个 epoch。目的不是追求最终质量，而是验证 tar 读取、增强、标签映射、反归一化、checkpoint 恢复和指标计算全部正确。B0 必须显著优于“每字段均值/中位数 + 每字段多数类”常数基线，否则停止后续训练并排查数据或损失。

### 生产候选 B1：多任务 ConvNeXt-Tiny

默认骨干为 ImageNet 预训练 ConvNeXt-Tiny，输入保持 `256×384`。全局特征后连接四类输出头：

- signed head：`768 → 67`，输出经 `tanh`。
- categorical heads：10 个独立线性层，每个字段输出自身类别数的 logits。
- strength head：`768 → 16`，输出经 `sigmoid`。
- color head：`768 → 6`，输出经 `sigmoid`。

分类头不能共享一个全局 allele 词表。6 个单类别字段在配置中标记为 constant class，导出 DNA 时写回 schema 中唯一类别。这样既减少无意义参数，也避免“100% accuracy”掩盖真实问题。

### 生产候选 B2：几何/颜色双视图

从同一张图生成两个几何一致、光度不同的视图，并将二者拼成一个 batch 通过共享骨干：

- 几何视图：允许较强亮度/对比度变化和随机灰度，用于 signed、categorical、strength。
- 颜色视图：只做轻微光照变化，保留肤色、眼色和发色信息，用于 color head。

推理时也生成几何视图和 RGB 视图，各做一次前向。双视图增加约一倍骨干计算，但能明显降低模型把肤色当作脸型捷径的风险。若延迟要求更严，可蒸馏到单视图小模型。

### 高级候选 B3：可微感知闭环

训练一个轻量“DNA → 图像特征”代理模型：输入为连续 DNA、类别 one-hot/softmax 和颜色坐标，目标为真实 CK3 图像的冻结视觉特征与人脸关键点。冻结代理后，在逆模型上增加特征循环损失，使“预测 DNA 对应的代理渲染特征”接近输入肖像特征。

该方案比在线启动 CK3 渲染器更稳定，也能用 softmax 概率保持可微。它属于 B1/B2 收敛后的增量实验，不能替代真实 CK3 回渲染评估。

## 损失函数与优化

### 主损失

先对每个字段独立求均值，再对字段求均值，避免类别数或张量长度决定任务权重：

```text
L = 1.0 * L_signed
  + 1.0 * L_class
  + 1.0 * L_strength
  + 0.2 * L_color
  + 0.05 * L_consistency       # B2 起启用
  + 0.10 * L_proxy_feature     # 仅 B3 启用
```

- `L_signed`、`L_strength`、`L_color`：SmoothL1，初始 beta 建议 `0.05`（归一化尺度）。
- `L_class`：字段独立交叉熵，单样本权重为 `max(target_strength, 0.05)`。
- 类别权重：按训练集频率的反平方根计算，并裁剪到 `[0.5, 3.0]`；权重只用训练集统计。
- `L_consistency`：原图与水平翻转图的几何输出一致性；不约束颜色视图。

先使用固定任务权重。只有当梯度日志证明某个任务持续主导时，再比较 GradNorm 或不确定性加权；不要一开始同时引入多种自动权重机制。

### 优化器与调度

| 配置项 | 推荐值 |
|---|---|
| 优化器 | AdamW，`betas=(0.9,0.999)`，`weight_decay=0.05` |
| 全局有效 batch | 256；显存不足时用梯度累积保持有效 batch |
| 头部学习率 | `3e-4` |
| 骨干学习率 | `1e-4`，可选 layer-wise decay `0.85` |
| 调度 | 5% warmup + cosine decay |
| 精度 | 优先 BF16；不支持时 FP16 + GradScaler |
| 梯度裁剪 | global norm `1.0` |
| EMA | decay `0.9999`，验证同时记录 raw 与 EMA |
| 随机种子 | 主实验 `20260718`；最终候选追加 2 个种子复验 |

### 在线增强

几何视图允许：水平翻转 `p=0.5`、旋转 `±3°`、平移不超过 3%、缩放 `0.95～1.05`、轻微模糊/JPEG 退化/噪声、面积较小的随机遮挡，以及模拟头发遮挡额头或头顶的上部遮挡。禁止大透视、激进随机裁剪和会改变五官比例的形变。

颜色视图使用同一组几何参数，仅加入弱亮度/对比度/饱和度扰动；不使用灰度化、明显色相偏移或大面积遮挡。所有增强参数写入 checkpoint 附带配置。

## 分阶段训练流程

| 阶段 | 训练内容 | 预计训练量 | 退出条件 |
|---|---|---:|---|
| P0 数据门禁 | 校验、统计、近重复、吞吐基准 | 无正式训练 | 全部数据门禁通过，配置与校验和冻结 |
| P1 B0 冒烟 | ResNet-18，10k 子集后全量 | 2 + 5 epoch | 恢复训练一致；优于常数基线至少 30% |
| P2 B1 热身 | 冻结骨干，仅训练 heads | 2 epoch | 各任务损失均下降，无 NaN/饱和 |
| P3 B1 全量 | 解冻全模型 | 18～24 epoch | 验证综合分数连续 5 次不改善 |
| P4 B2 稳健微调 | 双视图与一致性损失 | 8～12 epoch | 合成验证不退化，压力集和分组差距改善 |
| P5 B3 闭环实验 | 代理特征损失 | 5～10 epoch | CK3 回渲染指标显著改善，否则回退 B2 |
| P6 真人域适配 | 小规模人工配对 + 合成回放 | 5～10 epoch | 真人盲评、失败率和合成回归门禁通过 |

验证频率建议每 `0.25 epoch` 计算轻量参数指标，每个 epoch 完整验证一次。CK3 回渲染成本高，可每 2～3 个 epoch 对固定的 200 个验证样本执行，并在候选定版时扩大到完整渲染评估集。

## 评估与模型选择

### 参数级指标

- signed：每字段 MAE、原始 0～255 尺度 MAE、P90 误差。
- categorical：每字段 accuracy、macro-F1；同时报告全样本和 `strength≥0.10` 的可观察子集。
- strength：每字段 MAE、原始尺度 MAE、P90。
- color：每组二维坐标 L1 与欧氏距离，均换算回 0～255 网格。
- 稳健性：17 个组逐组指标、最差组、最好/最差差距；遮挡、模糊、曝光和 JPEG 压力集。

单类别字段不进入分类 accuracy 汇总。模型选择使用验证集综合分数，并设置硬门禁：任何任务明显退化、最差组差距扩大或回渲染质量下降，都不能仅凭总损失更低而晋级。

### CK3 回渲染闭环

对固定测试样本执行：预测标签 → `dna_normalizer.py denormalize` → 写入固定男性 DNA 模板 → CK3 标准相机、灯光、服装和无发型遮挡条件下渲染正脸与侧脸。记录：

- 对齐后 LPIPS/DISTS 或同类感知距离。
- 人脸 embedding cosine，相同模型版本全程固定。
- 关键点与脸部比例误差，包括眼距、鼻宽、下巴宽、头高和耳距。
- 至少 200 对的双盲人工 A/B：比较候选与 B1 基线哪个更像目标。

测试集只在最终候选冻结后运行一次。日常调参只用验证集与验证渲染子集。

### 初始验收门槛

绝对阈值应在 B1 首轮完成后基于验证分布冻结，以下先作为项目门槛：

1. 相对常数基线，signed 和 strength 的平均 MAE 至少降低 30%。
2. 对 `strength≥0.10` 的多类别字段，macro-F1 相对多数类基线至少提升 20 个百分点。
3. 17 个组中最差组的综合误差不得超过总体误差 15%；若超过，必须给出数据或模型修复。
4. B2/B3 在合成测试参数指标上不得较 B1 退化超过 2%，且固定回渲染集的感知指标必须有统计显著改善。
5. 真人照片发布前，人工盲评中最终模型相对 B1 的胜率应超过 60%，且明显失败样本率低于预先定义的产品阈值。

## 真人照片域适配

合成 CK3 截图具有固定镜头、背景、光照、无遮挡头型；真人照片具有姿态、光照、发型、胡须、妆容和成像噪声。合成测试分数不能证明真实照片可用。

建议建立 300～500 位有授权的男性真人小样本，覆盖肤色、年龄、脸型、发型、胡须、眼镜和拍摄设备。按身份划分 train/val/test，绝不能让同一人的多张照片跨集合。每张图先做人脸检测与关键点相似变换，再由 B2 生成多个候选，人工在 CK3 中选择或微调，保存最终 DNA 和“不可判定字段”标记。

微调时使用真人/合成约 `1:1` 混合回放，骨干学习率降至 `1e-5～3e-5`，头部 `5e-5～1e-4`，并保留合成验证门禁，防止灾难性遗忘。真实数据不足时优先训练最后两个 stage、归一化层和 heads，不应整网高学习率微调。

推理管线必须包含：人脸检测、关键点置信度、姿态/遮挡检查、相似变换、两视图构造、模型预测、置信度/越界检查、DNA 反归一化和模板写回。低置信度或严重侧脸应拒绝自动输出，并提示用户更换照片。

## 实验矩阵与消融

| 实验 | 改动 | 主要回答的问题 |
|---|---|---|
| E00 | 均值/多数类常数基线 | 数据标签本身有多难 |
| E01 | ResNet-18 单视图 | 训练链路是否正确 |
| E02 | ConvNeXt-Tiny 单视图 | 更强骨干带来的收益 |
| E03 | 去掉类别权重 | 类别不平衡处理是否必要 |
| E04 | 双视图 | 颜色捷径与压力集是否改善 |
| E05 | 去掉低强度 CE 权重 | 不可观察 allele 的噪声有多大 |
| E06 | 代理特征闭环 | 标签误差与视觉相似度能否统一 |
| E07 | 真人配对微调 | 真实照片域差距是否被缩小 |

每个关键候选至少用 3 个随机种子复验并报告均值/标准差。只对有明确假设的变量做一次一项消融；禁止同时改变骨干、增强、损失和数据划分后宣称单一因素有效。

## 资源预算与吞吐规划

正式估算采用实测公式：

```text
单 epoch 小时 = 459000 / 实测 samples_per_second / 3600
总 GPU 小时 = 单 epoch 小时 × epoch 数 × 视图系数 × 重跑系数
```

先以真实 WebDataset、AMP 和目标输入分辨率跑 2,000 step，前 200 step 预热后取中位吞吐。规划上，单张现代 24 GB GPU 建议预留 48 GPU 小时完成 B0～B2 的一次主线；B3 与三种子复验另计。显存不足时优先梯度累积，不降低输入到破坏耳朵和头型细节。双卡 DDP 目标扩展效率不低于 80%；若低于该值，先排查 JPEG 解码和分片 shuffle。

存储方面，保留原始 WebDataset、最近 3 个 checkpoint、最佳 raw/EMA checkpoint、日志和回渲染结果。checkpoint 仅保存必要状态，定期清理中间权重，但不能删除最终实验的配置、指标与校验和。

## 工程实现与可复现性

建议新增以下模块：`dataset.py`、`model.py`、`losses.py`、`train.py`、`evaluate.py`、`infer.py`、`configs/`、`tests/`。配置中显式保存字段顺序、每字段类别数、固定类别表、归一化规则、增强、损失权重和模板版本。

必须实现的自动化测试包括：

- schema 与模型输出维度一致；分类 logits 与字段词表逐项对应。
- normalize → denormalize 的往返误差满足整数舍入预期。
- 水平翻转不改变标签语义。
- checkpoint 恢复后下一 step 的损失与未中断训练在容差内一致。
- 单样本推理可生成可被 CK3 接受的 DNA 文本，非目标字段保持模板原值。
- val/test DataLoader 无随机增强、无重复和无 train 样本。

训练日志至少记录总损失、各任务/各字段损失、学习率、梯度范数、吞吐、GPU 显存、EMA 差异和 17 组验证指标。每次运行生成不可覆盖的 run ID，并导出机器可读 JSON 与人类可读报告。

## 风险与应对

| 风险 | 影响 | 预防与缓解 |
|---|---|---|
| 族群块名称口径冲突 | 分组结论被误标 | 以 manifest 的数字组为准；名称映射单独审计 |
| 合成到真人域差距 | 合成测试优秀但产品不可用 | 双视图、遮挡增强、授权真人小样本和独立真人验收 |
| DNA 逆问题多解 | 参数 MAE 与观感不一致 | 回渲染指标、代理特征闭环、人工 A/B |
| 低强度类别不可见 | 分类头学习噪声 | `max(strength,0.05)` 权重，另报可观察子集 |
| 单类别字段虚高 | 指标被 100% accuracy 污染 | 不训练其分类头，不纳入分类汇总 |
| 类别不平衡 | 少数 allele 召回低 | 字段内权重、macro-F1、混淆矩阵，不做全局过采样 |
| 肤色成为几何捷径 | 跨组和真人泛化恶化 | 几何/颜色双视图，race_group 不入模，分组门禁 |
| CK3 版本或渲染条件变化 | 闭环指标不可比 | 固定游戏版本、模组、相机、灯光、模板和截图区域 |
| UI 自动化不稳定 | 回渲染评估中断 | 小批量原子任务、失败重试、渲染 manifest 和截图校验 |

## 里程碑与交付物

| 周期 | 里程碑 | 交付物 |
|---|---|---|
| 第 1 周 | 数据门禁与 B0 | 数据审计报告、常数基线、可恢复训练链路 |
| 第 2 周 | B1 生产基线 | 模型、配置、完整参数指标、错误样本集 |
| 第 3 周 | B2 稳健模型 | 双视图模型、压力集与分组报告 |
| 第 4 周 | 回渲染闭环 | 固定渲染集、视觉指标、B3 决策报告 |
| 第 5～6 周 | 真人域适配 | 授权数据说明、真人模型、盲评与发布门禁 |

最终发布包应包含：模型权重、`dna_schema.json`、预处理/对齐配置、推理代码、固定 DNA 模板版本、模型卡、合成与真人评估报告、已知限制和回滚模型。第一版模型卡必须清楚写明“仅在当前男性 CK3 schema 与指定游戏/模组版本上验证”，不得外推到女性、儿童或未覆盖的 CK3 版本。

## 开始执行时的首批任务

1. 冻结并校验当前 manifest、schema 和 split seed；修订或弃用早期 `制作记录.txt` 的族群区间口径。
2. 编写 WebDataset DataLoader、常数基线和输出维度单元测试。
3. 完成 2,000 step 吞吐基准，确定单卡 batch 与梯度累积。
4. 运行 B0 并验证 normalize/denormalize/CK3 写回闭环。
5. 运行 B1，冻结首版绝对验收阈值；之后再进入 B2/B3 与真人域适配。

只要上述门禁按顺序执行，项目就能避免最常见的三类失败：数据泄漏、看似很高但无意义的分类准确率，以及“合成验证很好、真人完全不可用”的域偏移。
